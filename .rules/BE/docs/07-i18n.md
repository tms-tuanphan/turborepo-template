# Backend i18n

[← Mục lục](./README.md)

---

## Goals

- Stable **message keys** for client (FE translates).
- No raw DB/internal errors to clients.
- Locale from `Accept-Language` (or team header) — not request body.

---

## Keys

- Format: `errors.links.notFound`, `validation.links.slug.invalidFormat`
- Shared keys in `packages/api/src/common/i18n/keys.ts`
- Exceptions use keys: `throw new NotFoundException(I18nKey.Errors.Links.NotFound)`

---

## Locale detection

Rule: **do not** call `req.acceptsLanguages()` ad-hoc in services/controllers.

Recommended detection order:

1. `Accept-Language` header (preferred)
2. Query param `?lang=vi` / `?lang=en`
3. User preference in DB (after login) if available

Fallback:

- Default locale is `en`.
- If a translation key is missing for requested locale → fallback to `en` and **log a warning** with the missing key (no PII).

---

## Translation loading & caching

- Translation resources must be loaded **once** at app start (or cached) — do not reload per request.
- Multi-instance: use memory cache for static files; Redis cache only when you have dynamic translations.

---

## Validation

- `class-validator` messages reference keys, not hardcoded EN/VI strings.

Guidelines:

- DTO validates **format/type/required** only.
- Business rules (email already exists? order cancellable?) belong in **service** and throw business errors with i18n keys.
- Avoid translating field names in a brittle way; prefer keys like `validation.user.email.isEmail`.

---

## Business errors (recommended)

- Throw exceptions with **i18n key** as message (or `code`) and keep `details` structured (non-sensitive).
- Do not ship stack traces or raw DB errors to clients (especially in prod).

Use i18n for:

- Validation errors
- Business errors
- Email templates (confirmation, reset password)
- Push notifications (if applicable)

---

## Response shape (recommended)

```json
{
  "code": "errors.links.notFound",
  "message": "errors.links.notFound",
  "details": {}
}
```

No stack traces or Prisma messages in production responses.
